# ReAct: Synergizing Reasoning and Acting in Language Models 速读精要

这篇论文提出 ReAct，一种让大语言模型在同一条轨迹里交替生成“思考”和“动作”的提示范式。它想解决的问题不是单纯让模型更会推理，而是让模型在需要外部信息或环境反馈时，能一边推理、一边检索、一边行动，并把观察结果继续纳入后续推理。

ReAct 的关键价值在于把链式思考（Chain-of-Thought, CoT）的内部推理能力，和面向工具/环境的行动能力合在一起。推理让动作更有目标，动作让推理更有事实依据。论文在 HotpotQA、FEVER、ALFWorld 和 WebShop 上验证：ReAct 不只提升部分任务表现，也显著改善轨迹可解释性，让人能看出模型什么时候依赖内部知识、什么时候依赖外部观察。

## 核心问题

传统 CoT 只能在模型内部“想”，容易在事实性任务上幻觉；只让模型行动又缺少高层规划，容易在长任务中迷路或重复无效动作。**ReAct 的核心答案是：把语言思考也视为一种特殊动作，让模型在 Thought、Act、Obs 之间循环，用外部观察校正推理，用推理指导下一步行动**。

## 摘要

论文认为，语言模型的推理能力和行动能力此前大多被分开研究。ReAct 让模型以交错方式生成推理轨迹和任务动作：推理轨迹用于制定计划、跟踪状态、处理异常；动作则让模型查询 Wikipedia 或与文本环境交互，从而获得外部信息。实验显示，在知识密集型问答和事实验证任务中，ReAct 能降低 CoT 的幻觉和错误传播；在 ALFWorld 和 WebShop 这类交互式决策任务中，少量示例的 ReAct 也能超过需要大量训练数据的模仿学习或强化学习方法。

## 1 引言

引言从人类智能的“边想边做”出发：人做饭、查资料、完成任务时，并不是先一次性想完整计划再行动，而是在行动之间持续更新计划。语言推理在这里承担工作记忆、异常处理、目标分解和信息需求识别的作用。

论文指出 CoT 的限制在于它是静态的、黑箱的、只依赖模型内部知识。遇到需要最新事实或外部证据的问题时，CoT 容易把错误事实继续推下去。行动模型则相反：它能搜索、点击、导航，但如果没有高层语言推理，就很难分解目标、记录进度或解释为什么这么做。

Figure 1 是全篇主图，比较了标准提示、CoT、仅行动和 ReAct。最重要的信息不是版式，而是四种范式的行为差异：标准提示直接给答案；CoT 生成内部推理但不接触外部世界；仅行动能搜索但缺少推理组织；ReAct 则把 Thought、Act、Obs 串成闭环。

## 2 ReAct：协同推理与行动

ReAct 的形式化设定是一个智能体与环境交互。普通智能体在时刻 t 根据历史上下文选择外部动作；ReAct 扩展了动作空间，把自然语言思考也加入动作空间。语言思考不会改变外部环境，但会更新上下文，帮助后续决策。

这个设计的关键机制有三层：

- 思考可以分解任务、制定计划、提取观察中的关键信息、注入常识、记录子目标进度、发现异常并调整路线。
- 行动可以访问外部环境，例如 Wikipedia API、文本游戏环境或网页购物环境，并把观察结果反馈给模型。
- 上下文把 Thought、Act、Obs 累积起来，使模型下一步既能看到自己想过什么，也能看到环境返回了什么。

论文主要采用冻结的 PaLM-540B，通过少量人工写好的 in-context examples 让模型学会这种轨迹格式。知识推理任务使用较密集的 Thought-Act-Obs 循环；交互决策任务中动作很多，Thought 只在关键位置稀疏出现。

ReAct 的方法优势在于简单、通用、可解释。它不需要专门训练动作控制器，也不需要复杂的轨迹格式；人只要在示例轨迹中写出自然语言想法，就能让模型模仿这种“边想边做”的过程。

## 3 知识密集型推理任务

这一部分测试 HotpotQA 和 FEVER。任务设置故意不给支持段落，只给问题或声明，要求模型依赖内部知识，或通过一个很弱的 Wikipedia API 搜索信息。API 只有 `search[entity]`、`lookup[string]` 和 `finish[answer]` 三类动作，强调模型必须用语言推理决定搜什么、查什么、何时结束。

### 3.1 设置

HotpotQA 考多跳问答，FEVER 考事实验证。两者都需要事实检索和推理结合。论文使用的 Wikipedia API 并不是强检索器，只返回有限句子或相近实体，因此 ReAct 的能力主要来自“会不会把问题拆成合适的检索步骤”，而不是靠检索系统本身兜底。

### 3.2 方法

ReAct prompting 在 HotpotQA 上用 6 个示例，在 FEVER 上用 3 个示例。示例轨迹包含多轮 Thought、Act、Obs：Thought 可以写“我需要先搜索 x，再找 y”，也可以写“这段没有回答问题，我要换关键词”，最后再综合答案。

对比方法包括标准提示、CoT、CoT self-consistency、仅行动 Act，以及 ReAct 与 CoT-SC 的组合。组合策略很有启发：如果 ReAct 步数用完还没答出，就回退到 CoT-SC；如果 CoT-SC 多次采样没有形成高置信多数答案，就切到 ReAct 让模型查外部信息。

### 3.3 结果与观察

在 PaLM-540B 上，ReAct 在 FEVER 上优于 CoT，在 HotpotQA 上略低于 CoT，但优于仅行动 Act。最强结果来自 ReAct 和 CoT-SC 的组合：HotpotQA 上 ReAct→CoT-SC 达到 35.1 EM，FEVER 上 CoT-SC→ReAct 达到 64.6 accuracy。

更重要的是错误类型。论文人工分析 HotpotQA 轨迹发现，CoT 的失败中大量来自幻觉事实；ReAct 因为会查询外部信息，成功轨迹更 grounded。代价是 ReAct 受检索质量和轨迹格式约束影响更大：搜索不到有用信息、重复生成前一步动作，都会让它失败。

Figure 2 展示 ReAct+CoT-SC 在不同采样次数下都能稳定超过单独 CoT-SC，说明外部行动和内部推理是互补的。Figure 3 则显示微调后 ReAct 表现更强：用 3000 条正确轨迹微调小模型后，ReAct 优于只微调标准答案或 CoT，因为它学到的是“如何查询和利用外部知识”的技能。

## 4 交互式决策任务

这一部分转向 ALFWorld 和 WebShop。这里的问题不再是回答事实，而是在长程环境中做动作。困难在于状态多、路径长、反馈稀疏，模型必须分解目标、记住进度，并在环境反馈不符合预期时调整计划。

### ALFWorld

ALFWorld 是文本家庭环境，任务包括拿取、清洁、加热、冷却、查看、放置两个物品等。ReAct 的提示轨迹为每类任务人工标注 3 条，Thought 主要用于目标分解、子目标跟踪、下一步计划和常识推断。

结果很直接：ReAct 最好一次平均成功率 71%，明显高于 Act 的 45% 和 BUTLER 的 37%。这说明在长程文本环境里，缺少 Thought 的行动模型容易忘记当前状态或不会拆目标；而稀疏推理能显著改善探索和计划。

### WebShop

WebShop 模拟网页购物，模型需要根据用户指令搜索商品、筛选属性、选择选项并购买。这里观察文本噪声更大，商品标题、描述和选项都不规整。

ReAct 在 WebShop 上取得 66.6 score 和 40.0 success rate，比 IL+RL 的 28.7 success rate 高 10 个百分点以上。它的优势来自 Thought 能把用户需求和网页观察之间的语义差距补起来，例如判断某个选项是否符合价格、颜色、尺寸等约束。

### 内部推理与外部反馈的差别

论文还比较了 ReAct 和 Inner Monologue 风格的 ReAct-IM。ReAct-IM 更像是密集描述外部状态，而不是主动进行高层推理。结果 ReAct 明显优于 ReAct-IM，说明关键不是“多写环境反馈”，而是要有真正的目标分解、常识推断和进度管理。

## 5 相关工作

论文把相关工作分成两条线：语言模型推理和语言模型决策。CoT、self-consistency、least-to-most、STaR 等方法关注内部推理；WebGPT、SayCan、Inner Monologue 等方法关注行动和环境交互。ReAct 的位置在两者之间：它不是只让模型想，也不是只让模型做，而是把思考、动作和观察放进同一条可检查轨迹。

## 6 结论

ReAct 是一个非常简单但影响很大的范式：**让 LLM 以可读的 Thought-Act-Obs 轨迹解决任务，把推理变成行动的一部分，也把行动反馈变成推理的依据**。它在事实任务中减少幻觉，在交互任务中改善计划与状态跟踪，并且天然增强可解释性。

它的边界也清楚：复杂动作空间需要更多示例，长提示会受到上下文窗口限制；如果检索结果差，ReAct 也会被带偏；提示式 ReAct 还可能出现重复动作或循环。论文最后认为，更多高质量轨迹微调、多任务训练，以及与强化学习结合，可能进一步释放 ReAct 的能力。
