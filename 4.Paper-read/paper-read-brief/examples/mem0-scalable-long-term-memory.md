# Mem0: Building Production-Ready AI Agents with Scalable Long-Term Memory 速读精要

这篇论文提出 Mem0 和 Mem0g 两套面向生产 AI Agent 的长期记忆架构。它关注的不是“如何把更多上下文塞进模型”，而是如何把长对话中真正重要的信息抽取、更新、检索出来，让 Agent 在多轮、多会话、长时间跨度中保持一致性，同时控制延迟和 token 成本。

Mem0 的核心是自然语言记忆：从新对话片段中抽取候选事实，再和已有记忆比较，决定新增、更新、删除或忽略。Mem0g 则加入图记忆，把实体和关系显式建成图，更适合表达时间顺序、人物关系和跨事实连接。论文在 LOCOMO 长对话记忆基准上验证，两者在质量、延迟和成本之间取得了比传统 RAG、全上下文和多种记忆系统更适合生产部署的平衡。

## 核心问题

固定上下文窗口无法真正解决长期记忆问题。上下文变长只会推迟溢出，而且长历史里往往混有大量无关内容，模型未必能稳定找回关键事实。**Mem0 的核心答案是：把原始对话压缩成可维护、可检索、可更新的长期记忆层；必要时再用图结构补充关系和时间推理能力**。

## 摘要

论文指出，LLM 虽然能生成连贯回答，但缺少跨会话持久记忆。Mem0 通过动态抽取、整合和检索显著信息来维护长期对话状态；Mem0g 在此基础上加入图表示，用实体节点和关系边捕捉复杂关联。实验在 LOCOMO 上比较了已有记忆系统、RAG、全上下文、开源记忆方案、OpenAI 记忆能力和 Zep。结果显示，Mem0 在多类问题上优于多数现有方法，并显著降低延迟和 token 成本；Mem0g 在整体 LLM-as-a-Judge 分数上最高，尤其有利于时间和开放域问题。

## 1 引言

引言从人类记忆讲起：人能记住长期偏好、经历和关系，并据此做后续判断。AI Agent 如果没有持久记忆，就会在不同会话之间忘记用户偏好、重复提问，甚至给出与过去信息矛盾的建议。

Figure 1 用饮食偏好举例：用户曾说自己是素食且不吃奶制品，下一次询问晚餐建议时，没有记忆的系统可能推荐不合适食物；有记忆的系统会保留这些约束并给出符合偏好的答案。图中真正强调的是“跨会话连续性”，不是单轮上下文理解。

论文进一步说明，大上下文不是根本解法。即使上下文窗口扩到 128K、200K 乃至更长，长期关系仍会超过窗口；而且真实对话主题跳跃，关键事实可能被大量无关内容淹没。记忆系统必须选择性存储、合并相关概念，并在需要时检索。

论文贡献包括：提出 Mem0 的动态记忆架构；提出图增强版 Mem0g；在 LOCOMO 上系统比较多类基线；证明记忆式方法在质量接近甚至超过多数方案的同时，大幅降低延迟和 token 成本。

## 2 方法

论文提出两套架构。Mem0 用自然语言事实作为记忆单元，强调快速抽取和更新；Mem0g 把记忆表示成有向标注图，强调实体关系和时序结构。两者都面向持续对话，而不是离线一次性索引。

### 2.1 Mem0

Mem0 的完整流程分成 extraction 和 update 两个阶段。

抽取阶段处理一对新消息 `(m_{t-1}, m_t)`，通常是一轮用户与助手交互。为了不只看当前消息，系统还会取两类上下文：一是数据库里的对话摘要 `S`，代表全局语义；二是最近 `m` 条消息，代表局部时间上下文。它们和当前消息对一起组成提示 `P`，由 LLM 抽取候选记忆集合 `Ω`。

更新阶段维护记忆库的一致性。对于每条候选记忆，系统先用向量检索找出 top-s 相似旧记忆，再把候选记忆和相似记忆交给 LLM function calling。LLM 直接选择四种操作之一：

- ADD：不存在等价记忆时新增；
- UPDATE：旧记忆需要补充信息时更新；
- DELETE：新信息与旧记忆冲突时删除；
- NOOP：无需修改记忆库时忽略。

Figure 2 展示的关键点是：Mem0 不是简单“抽一句就存一句”，而是把抽取和更新分开，用相似记忆比较来避免冗余、冲突和过时信息。实验配置中，Mem0 使用最近 10 条消息作为局部上下文，检索 10 条相似记忆，LLM 操作使用 GPT-4o-mini。

### 2.2 Mem0g

Mem0g 把记忆表示为有向标注图 `G=(V,E,L)`：节点是实体，边是关系，标签表示实体类型。每个实体节点包含类型、语义 embedding 和创建时间；关系用三元组表示，例如某人住在某地、某事件发生在某天。

抽取过程分两步：先用 LLM 从对话中抽取实体及类型，再生成实体之间的关系三元组。这里的实体不只是人名或地点，也包括对象、概念、事件、属性和偏好，只要它未来可能影响回答，就可以进入图。

更新时，Mem0g 会根据实体 embedding 查找已有节点，决定创建新节点、复用旧节点或补边；如果新关系和旧关系冲突，系统不会简单物理删除，而是标记旧关系失效，从而保留时间推理所需的历史痕迹。

检索时，Mem0g 有两条路径：实体中心检索先识别查询中的关键实体，再沿入边和出边扩展相关子图；语义三元组检索则把整个查询编码后，与关系三元组文本表示匹配。两者结合，使 Mem0g 同时能处理明确实体问题和更开放的概念问题。

## 3 实验设置

### 3.1 数据集

实验使用 LOCOMO，这是用于评估长对话记忆的数据集。它包含 10 段长对话，每段约 600 轮、平均 26000 tokens，并跨多个会话展开。每段对话配有约 200 个问题，分为 single-hop、multi-hop、temporal 和 open-domain。论文排除了 adversarial 类问题，因为没有 ground truth answer。

### 3.2 评价指标

论文把指标分成质量和部署两类。质量指标包括 F1、BLEU-1 和 LLM-as-a-Judge。作者特别强调，F1/BLEU 对事实错误不敏感，例如月份答错但词重合很多仍可能得高分，所以引入 judge 模型评估事实准确性、相关性、完整性和上下文适配。

部署指标包括 token consumption 和 latency。token consumption 衡量回答问题时检索出来、作为上下文输入模型的 token 数；latency 分 search latency 和 total latency，分别衡量检索时间和完整回答生成时间。

### 3.3 基线

基线覆盖六类：已有 LOCOMO 方法（如 ReadAgent、MemoryBank、MemGPT、A-Mem）、开源记忆系统 LangMem、标准 RAG、全上下文处理、OpenAI 记忆能力，以及 Zep 这类记忆管理平台。RAG 基线把整段对话切成不同 chunk size，并设置 top-k 检索；全上下文基线则直接把完整历史塞入模型。

这个基线设计的价值在于，它不仅比较“答得准不准”，还比较“生产上能不能用”。全上下文可能质量高，但延迟和成本高；RAG 便宜但容易检索噪声；记忆系统则试图在中间找到更优折中。

## 4 结果、分析与讨论

### 4.1 记忆系统整体表现

Table 1 比较不同方法在四类问题上的 F1、BLEU-1 和 judge 分数。Mem0 在 single-hop 上最强，judge 分数达到 67.13；在 multi-hop 上也领先，judge 分数为 51.15。Mem0g 在 temporal 上表现最好，judge 分数为 58.13；open-domain 上 Zep 略高，但 Mem0g 也非常接近。

这一结果说明，Mem0 的自然语言记忆对单点事实和多跳整合已经足够有效；而 Mem0g 的图结构在时间顺序、事件关系和开放域整合上更有优势。但图结构不是处处更好：在 single-hop 和 multi-hop 上，Mem0g 并没有超过 Mem0，说明图带来的结构化能力也会带来额外复杂度。

### 4.2 跨类别分析

跨类别结果揭示了两种记忆表示的分工。自然语言记忆适合快速、直接的事实检索，表示紧凑、延迟低；图记忆适合需要关系路径、时间顺序和实体连接的问题。**Mem0 和 Mem0g 的区别不是简单的“图更高级”，而是不同问题类型需要不同记忆结构**。

这对生产系统很关键：如果大多数请求是用户偏好、事实属性、简单历史信息，Mem0 的密集自然语言记忆可能更经济；如果业务强调事件时间线、人物关系、长期状态演化，Mem0g 的图结构更值得引入。

### 4.3 与 RAG 和全上下文比较

Table 2 显示，所有 RAG 配置中最好的 overall judge 分数约 61%，Mem0 达到 66.88%，Mem0g 达到 68.44%。这说明把长对话切块检索并不等价于长期记忆：chunk 会带入大量噪声，而记忆抽取把对话压成更精确的事实表示。

全上下文方法 judge 分数约 72.90，仍然最高，但它每次都要处理约 26000 tokens，p95 总延迟达到 17.117 秒。相比之下，Mem0 p95 总延迟为 1.440 秒，Mem0g 为 2.590 秒。论文强调，这就是生产部署中的关键折中：全上下文可能略准，但成本和响应速度很难接受；记忆式方案以较小质量差距换来大幅效率提升。

### 4.4 延迟分析

Mem0 的 search latency 最低，p50 为 0.148 秒，p95 为 0.200 秒；total latency p50 为 0.708 秒，p95 为 1.440 秒。Mem0g 因为要处理图关系，延迟更高，但 p50 total 仍为 1.091 秒，p95 total 为 2.590 秒，并且 overall judge 分数最高。

Figure 4 的重点是把质量和延迟放在一起看。LangMem 的搜索延迟非常高，full-context 没有搜索开销但总生成很慢，OpenAI 记忆响应快但这里没有计入记忆预抽取过程。Mem0 的优势在于 search 和 total latency 都稳定低，适合交互式 Agent。

### 4.5 记忆系统开销

论文还分析记忆构建的 token 开销。Mem0 每段对话平均约 7k tokens，Mem0g 约 14k；Zep 的记忆图超过 600k tokens，甚至比原始完整对话还大很多。作者认为 Zep 的节点摘要和边事实存在大量冗余，而且图构建涉及异步后台处理，新增记忆后不能立即稳定检索。

Mem0/Mem0g 的优势在这里变得更明确：它们不仅检索快，而且记忆构建和可用性更接近实时。对生产 Agent 来说，用户刚说的新偏好必须马上可用，否则记忆系统的体验会断裂。

## 5 结论与未来工作

论文总结说，Mem0 和 Mem0g 分别用紧凑自然语言记忆和结构化图记忆解决固定上下文窗口的长期记忆问题。Mem0 擅长快速检索和低成本部署，Mem0g 擅长关系和时间推理。二者在 LOCOMO 上相较多类记忆系统取得更好的综合表现，并相对全上下文显著降低 p95 延迟。

局限和未来方向也很清楚：Mem0g 的图操作还需要优化，以降低延迟；未来可以探索层次化记忆，把自然语言记忆的效率和图结构的关系表达结合起来；还可以把这些记忆框架扩展到程序推理、多模态交互等更复杂场景。

这篇论文对 Agent 工程的启发是：**长期记忆不是“向量库 + top-k 检索”的小改造，而是一套持续抽取、冲突处理、时间更新和按需检索的状态管理系统**。Mem0 的贡献在于把这套系统做成了更接近生产约束的架构，而不是只追求离线 benchmark 分数。
